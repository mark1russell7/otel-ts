    What init() starts
    
          
      
            
    • Spans for the document load, fetch, XHR, clicks and long tasks.
      • 
            
    • The W3C trace context on requests to the origin of the page.
      • 
            
    • A batch of spans, a batch of logs and a periodic metrics reader.
      • 
            
    • A flush each time the page goes to hidden or frozen.
      • 
          
    
        
    
      
    

      
    
        
    How this page works
    
        
      
          
    1. Before init(), the page replaces fetch with a small stub.
      2. 
          
    2. The fetch instrumentation of the package wraps that stub. The OTLP exporters call the stub directly, so an export makes no span.
      3. 
          
    3. The stub keeps each POST to https://collector.invalid, and it answers 200. That host name does not resolve.
      4. 
          
    4. The page decodes the body of each POST, and it draws the result. The console has the same records in otelLab.exports().
      5. 
        
    
        
    The button Fetch a file gets a real file from this site. The button Call another origin gets its answer from the stub, and the page tells you so.
    
        
    Faro stays off on this page, because the page shows only the OTLP exports. init() starts Faro only with faroCollectorUrl. Faro has no tracing of its own, so with Faro on, each request also has one span.
