# Roadmap

This file is the plan of otel-ts. The Status page of the site reads it. The design of the items from C1 is in [CONTEXT-DESIGN.md](CONTEXT-DESIGN.md).

| ID | Item | Status | Priority | Summary |
| --- | --- | --- | --- | --- |
| O1 | The site with a live lab | done | P2 | The site at GitHub Pages starts the real `init()` in the browser. A stub in the page catches each OTLP export, and the page shows it in a waterfall and on a wire. |
| O2 | Faro in the lab | done | P3 | The second copy of each fetch span came from the `TracingInstrumentation` of Faro, in each app with `faroCollectorUrl`, not only in the lab. 0.7.0 (#90) removes it: Faro reads the context of otel-ts and has no tracing of its own, and the requests of Faro make no span. A test with the real Faro holds it. The lab starts Faro with a collector on its stub: a fourth lane on the wire, a list of the Faro items with a link to their span, and a mark on the span in the waterfall. The tests of the site and the site check hold one span for each fetch, and the IDs of the span on each Faro item (#94). The request monitor of Faro replaced `fetch()` without `__original`, so each OTLP export made a span. 0.7.4 (#102) keeps `__original` on the wrapper of Faro. |
| C1 | The design of one context, and the talk | done | P1 | The design doc, then the decisions D1 to D5 with the strategist and Mark. The build starts after the talk. |
| C2 | The entry `/context` | done | P1 | `defineContextKeys`, `withContext`, `contextValue` and `withInternalCall`, on `@opentelemetry/api` only. Needs C1. |
| C3 | The processors of the context keys | done | P1 | Copy each named key of the baggage to each span and log record. A metric view removes each key of high cardinality. The `session.id` processors become a case of them. Needs C2. |
| C4 | The propagator: baggage on internal calls only | done | P1 | W3C trace context on each call, baggage only with the internal mark, the W3C limits, and one registration only. Needs C2. |
| C5 | `/node` registers the context also with export off | done | P1 | AsyncLocalStorage, the propagator of C4 and the processors of C3, with or without a collector. Needs C3 and C4. |
| C6 | The browser entries use the same parts | done | P1 | `init()` registers the propagator of C4 and the processors of C3. Needs C3 and C4. |
| C7 | The propagation gate | done | P1 | A test helper of rigor: in-memory exporters, one id from client to server to logs, metrics and traces, a flip test, and "no read" lines. Needs C2. |
| C8 | `@procedures/client` sends the context | done | P1 | Client and host spans of the OTel API (option `apiSpans`). The registered propagator writes `traceparent`, `tracestate` and `baggage` on HTTP, WebSocket and port calls, with `baggage` only on an internal call. The W3C helpers of `tracing/traceparent.ts` are deprecated. client#519, released with the next client train. |
| C9 | Local storage for services | done | P2 | grafana-infra#60: the stack keeps the data of the Node services (`startNodeTelemetry()`, OTLP to Alloy) and links it. A log line opens its trace (`trace_id` in Loki), a span opens the lines of its trace, and a metric opens its traces (the exemplars of the span metrics of Tempo, kept in Mimir). The Verify workflow checks each link with a sample service. Tail sampling moved to C18. The home cluster waits on its talk. Done on 2026-11-09. Needs C5. |
| C10 | `@procedures/peer` runs each handler in the context of its caller | done | P1 | client#527: the engine runs each handler in the context of its caller. The trace always goes in. The baggage goes in only from a trusted caller: a local request, a request with the token of the server, or a request that the option `trustBaggage` names. The MCP face reads the trace keys of `_meta`. `mark` reads `TRACEPARENT`, `TRACESTATE` and `BAGGAGE`. Released with the next client train. `hostPolicy()` does not pass `trustBaggage` yet. Done on 2026-11-09. Needs C8. |
| C11 | `@mark1russell7/service` logs carry the ids | done | P1 | `trace_id` and `span_id` on each log line (systems#441), and its HTTP and gRPC parts read and send the context, held by the propagation gate (systems#445). Needs C4 and C7. |
| C12 | The gate is green on each transport in CI | done | P1 | client and systems run the gate of C7 on each of their transports, as a required check. client (client#530): local, HTTP, WebSocket, port, and the engine with a nested call. systems (systems#458): local, the HTTP client and transport, and the gRPC client. A mutation check fails the gate on each repo. The KPI reads 4 of the 6 kinds of transport. MCP and CLI go to C19. Done on 2026-11-09. Needs C8, C10 and C11. |
| C13 | The inherited repositories | done | P2 | otel-ts, AsyncBrowserContext, lag and grafana-infra: green CI, the checks CI OK and Security OK, and no open alert. otel-ts 0.6.0 (#83: the OpenTelemetry 2.12 line fixes the baggage advisory of `@opentelemetry/core`, and the fetch and XHR spans get the stable HTTP names), AsyncBrowserContext#53, lag#139 and lag#141 (otel-ts `^0.6.0`, and core 2.12 under the pin of E8). Done on 2026-11-09. |
| C14 | KPI milestones | done | P2 | 2 to 5 measured milestones on the KPI page, for example the count of transports on which the gate is green. |
| C16 | Exemplars from the SDK | blocked | P3 | Blocked upstream: issue open-telemetry/opentelemetry-js#5147, and the open PR #6830 that adds exemplars. The JS metrics SDK records no exemplars today (2.6.1 and 2.12.0; 3.1.0 has no exemplar code). When an aggregator records them, turn them on, so a metric point carries its trace id, and the gate reads one. Until then, the span metrics of Alloy give the link (C18). Needs C3. |
| C17 | The copies of mulberry32 move to rigor-generators | done | P3 | Atlas CA14, verdict move: `scripts/send-sample-data.mjs` of grafana-infra (grafana-infra#61, merged) and `test/interleave/order-variation.test.ts` of AsyncBrowserContext (AsyncBrowserContext#54, merged) use `mulberry32` of `@mark1russell7/rigor-generators`, not a local copy. The sequence of each seed does not change. Split from C13. |
| C18 | Tail sampling, with the span metrics before the sampler | done | P2 | grafana-infra#64: the span metrics and the service graph move from Tempo to the connectors of Alloy, before a new tail sampler. The sampler keeps each trace with an error, each trace of 2 s or more, and `TRACE_SAMPLE_PERCENT` of the others (default 100). A transform keeps the metric names and labels of Tempo, so the dashboards and the service map do not change. The exemplar label is `trace_id`. Verify runs a phase at 0 percent: Tempo keeps only the failed trace, and the span metrics count each request. Done on 2026-11-09. Split from C9. Needs C9. |
| C19 | The gate on the MCP and CLI entries | done | P2 | MCP and CLI are entries, not transports of the client. C10 made them read the context: the MCP face reads the trace keys of `_meta`, and `mark` reads `TRACEPARENT`, `TRACESTATE` and `BAGGAGE`. client#543 runs the gate on both, so the KPI reads 6 of 6. Split from C12. Needs C10 and C12. |
| C15 | One OpenTelemetry core for lag and otel-ts | done | P3 | Decision D7: no new package. lag 0.5.0 takes its types from `@opentelemetry/api`, and `lag/meters` is the home of the meter combinators (lag#142). otel-ts 0.7.2 and client check the W3C IDs with the API (#98, client#545). 0.7.3 has `lagDeps()` in the entry `/lag` (#99). lag-hud 0.3.0 takes `fanOutMeter` and the meter types from `lag/meters` (lag-hud#78). Done on 2026-11-09. |
| C20 | One capture of the SDK for tests | done | P3 | Four test files had their own copy of the OpenTelemetry capture for tests: client (C12 and C19), systems and otel-ts. rigor#177 adds one home: `captureTelemetry()` in `@mark1russell7/rigor-testkit/otel` 0.1.2. One PR for each copy moved it there: #106, systems#473, client#551 and client#552. The map of homes names it (template#295). Done on 2026-11-09. |
| C21 | The users of otel-ts take its current line | in progress | P3 | systems and lag tested with old lines of otel-ts: the service of systems with `^0.4.0`, the integration tests of lag with `^0.6.0`. systems#478 and lag#149 move both to `^0.7.4`, with one OpenTelemetry line in each lockfile. The breaks of 0.5 to 0.7 are in the browser entries only. The E8 experiments of lag keep their `github:` pin, because E8 records that commit in its result. Needs C20. |
| C22 | The break of D6: client drops its own W3C code | blocked | P3 | Decision D6: with no SDK, `@procedures/client` keeps its own W3C code, now `@deprecated`. A later break removes that code. It waits until the site, MiniMongo, Graph and jarvis each register an SDK in a released version. Needs C8. |
| C23 | OpenTelemetry JS 3.x | blocked | P3 | Blocked upstream: OpenTelemetry JS 3.0 is not released. On 2026-11-09 the npm `latest` is 2.12.0, and 3.x is only the canary `3.0.0-development.0`. When 3.0 is released, otel-ts, lag and rigor-testkit move to it together, and the gate shows that the context still goes through. |
